## Verification performed

- Reviewed the whole `5705eb7` diff against `AGENTS.md`, `SPEC-005`, `PLAN-006`,
  `ADR-0002`, the endpoint catalog, and the sibling admin services.
- Reproduced the lock-scope regression in `HIGH-01` on real MySQL 8.4 at
  `REPEATABLE READ`: with 300 windows concentrated on one room and the candidate
  index present, `EXPLAIN` on the captured overlap `SELECT ... FOR UPDATE` chose
  `idx_room_times_status_range`, and a second session's overlap read for a
  **different** room failed with `Lock wait timeout exceeded` after 2s. Pinning the
  read with `USE INDEX (idx_room_times_room_status_from)` returned the plan to the
  room-scoped index and the cross-room read completed in 1ms.
- Mutation-checked the new guard: re-creating the rejected index inside the test
  makes `keeps window creation independent across physical rooms` fail with that same
  lock-wait timeout.
- Measured `limit`/`offset` against `skip`/`take` on the public page query: 3
  statements drop to 2, but the row query loses `idx_rooms_status_type` (`key: null`,
  full scan) and still sorts, so the shape was left as it is.
- Verified the `IntersectionType` compositions keep validation and OpenAPI metadata:
  the generated document still lists all eleven `GET /rooms` parameters, HTTP requests
  still return field-level errors for `checkIn`, and the inherited `page`/`pageSize`
  defaults still apply over HTTP.
- Full gate after the fixes: `MYSQL_PORT=13306 npm run verify` exit 0.

## Residual risk and follow-up

- The fixes were authored by the same agent that wrote the slice, so `P3-T06` owes
  this slice a review by someone who did not write it.
- The availability path still scans `room_times` end to end. Any index that helps it
  is also usable by the room-scoped overlap `SELECT ... FOR UPDATE`, so it must be
  introduced together with the Phase 4 window-locking review and a cross-room lock
  test, never on read evidence alone.
- Phase 4 replaces the containment condition with room-wide `CONFIRMED` exclusion.
  `stayContainmentCondition` is the single place that changes, and booking date
  columns must declare `utc: true` for the reason `REVIEW-018` records.
- The public reads now hold a transaction for their duration. That is a consistent
  snapshot, not a locking read, but it does occupy a connection for three
  statements; connection-pool sizing belongs to the Phase 3 exit review.
- Public payloads deliberately omit room images until the image slice ships them;
  `PublicRoomResponseDto` is the only place they will be added.
